Project Tesselle02
02 · The solution

One agent. One brief. Four credible routes.

MissionLock - the intent safeguard

A living, versioned brief: must-haves, flexible preferences, budget, unknowns and acceptance checks. Nothing material changes without the customer's explicit decision.

Fulfilment - buy, source, customise or make

Every route is checked against the same brief, requirement by requirement. When nothing fits, a maker gets a clean brief - and their counteroffer becomes the customer's decision, never a silent swap.

Project Tesselle03
03 · How MissionLock works

Language models propose. Deterministic code decides.

  • Fit verdicts - meets / possible with a change / not suitable, computed in code from structured requirements.
  • Quote deviations - every offered spec is diffed against the brief version it answers.
  • Approval gates - no stale quote, no changed brief, no unmet must-have, no duplicate order.
  • Honest uncertainty - photo sizes are "Needs checking"; unknown charges are never folded into a total.

Gemini agents only explain the verdicts - a cheaper or prettier item that breaks a must-have is never promoted.

Project Tesselle10
10 · Trust by design

Honest by default. Safe by construction.

  • Four unmistakable visual states: concept, existing product, supplier proposal, approved sample.
  • Must-haves change only through a labelled decision that creates a new brief version.
  • "No suitable match found in the sources checked" - an honest dead end beats a fabricated success.
  • Demo sellers are fictional and AI-simulated; orders are sandbox - and labelled so.
  • Sellers receive a privacy-filtered brief - no name, address or home imagery unless the customer opts in.
  • The conversational agent cannot send requests, accept seller changes or approve spending.
  • Vertex AI only, one service identity, no API keys; billing labels on every Gemini call.
  • Public-demo cost guard caps daily model and image calls.
